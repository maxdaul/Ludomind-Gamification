# Платформа геймификации

Версия на основе `dev-final` с исправлениями по ТЗ и ТП.

## Запуск Docker

Для уже настроенного проекта:

```console
docker compose up -d --build
```

Открыть http://localhost:8000. Для остановки использовать `docker compose stop`.
Не удаляйте тома базы, если данные нужны.

### Запуск с тестовыми аккаунтами и соревнованиями

При первом запуске выполните из корня проекта:

```console
python scripts/setup_local_env.py
docker compose up -d --build
```

Если файлы `.env.local`, `.env.db.local` и `.env.grafana.local` уже созданы, выполните сразу `docker compose up -d --build`. При запуске backend подготавливает схему PostgreSQL и загружает `db_backup.sql` в пустую базу. Пользовательские данные при повторных запусках сохраняются. Для входа используйте прежний email и пароль тестового аккаунта.

Для ручного импорта можно запустить `python scripts/restore_demo_db.py`. В дампе находятся тестовые пользователи с хешами паролей, соревнования, справочники и привязки к аккаунтам Moodle.

Содержимое курсов, зачисления и прогресс хранятся в Moodle. Для их отображения задайте в `.env.local` адрес веб-сервиса исходного Moodle в `MOODLE_WS_URL` и его действующий `MOODLE_WS_TOKEN`.

### Запуск с пустой базой

Если локальной конфигурации ещё нет, создайте её через `python scripts/setup_local_env.py`. Чтобы отключить загрузку тестовых данных, задайте `INIT_DEMO_DB=false` в `.env.local` до первого запуска backend.

```console
docker compose up -d --build db
docker compose run --build --rm backend python -c "from database import init_db; init_db()"
docker compose up -d --build
```

Для совершенно новой базы перед инициализацией добавьте в `.env.local` параметры `BOOTSTRAP_ADMIN_EMAIL`, `BOOTSTRAP_ADMIN_PASSWORD` и при необходимости `BOOTSTRAP_ADMIN_USERNAME`. Они создают первого администратора только при отсутствии такой записи; существующий аккаунт и его пароль не заменяются. После создания удалите bootstrap-пароль из локальной конфигурации. На текущем стенде существующие аккаунты сохранены.

Генератор создаёт `.env.local`, `.env.db.local` и `.env.grafana.local` с разными случайными секретами. Эти файлы исключены из Git и Docker-образа. Повторно генератор их не заменяет. Для существующей базы смена POSTGRES_PASSWORD в env не меняет пароль роли PostgreSQL автоматически; пароль роли и DB_PASSWORD должны совпадать. Не перегенерируйте конфигурацию существующего стенда без синхронной настройки БД.

Для существующего стенда сохраняйте его локальный `docker-compose.override.yml`, если он задаёт отдельный том базы. Этот файл исключён из Git. Инициализация не запускается автоматически при каждом старте. Существующие пользовательские данные при обычном запуске сохраняются.

## Ключи интеграций

Без YANDEX_API_KEY задачи сохраняются с исходным текстом и фиксированными 10 баллами. Чтобы включить YandexGPT, задайте `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` в `.env.local` и пересоздайте backend (`docker compose up -d backend`). Модель `gpt://<каталог>/yandexgpt/latest` запрашивается через Text Generation API. При ошибке настроенного сервиса задача не сохраняется, пока запрос оценки не завершится успешно. Аналогично MOODLE_WS_TOKEN задаётся в локальном окружении. Для переменных интеграций локальный env-файл имеет приоритет над пустыми значениями по умолчанию. При отсутствии Moodle-токена функции Moodle недоступны; локальная статистика задач работает независимо.

## Менеджеры и уведомления о сроках

Администратор открывает «Админ-панель → Пользователи → Редактировать» и выбирает менеджера сотрудника. У сотрудника может быть один менеджер. Существующие сотрудники остаются без назначения, пока администратор не выберет его. Менеджер может назначать задачи только закреплённым сотрудникам и видит их персональную статистику. Список соревнований и общий рейтинг остаются общими.

Сервис `deadline-notifications` раз в минуту проверяет сроки. Сотруднику отправляется одно напоминание в течение последних 24 часов, менеджеру — одно письмо после просрочки, если он назначен. Завершённые задачи и задачи на подтверждении исключены. Для перенесённого срока учитывается новая дата. Если внешний вызов завершился ошибкой, повтор выполняется не раньше чем через 15 минут.

Все письма используют существующий HTTPS API по `YC_MAIL_FUNCTION_URL`. Для закрытой функции добавьте `YC_MAIL_FUNCTION_API_KEY` в `.env.local`. Приложение передаёт ключ в заголовке `Authorization: Api-Key`. Postfix может находиться за внешним API, но в составе этого проекта он не развёрнут. После настройки пересоздайте `backend` и `deadline-notifications` командой `docker compose up -d backend deadline-notifications`.

## Moodle и Grafana

Для зачисления у пользователя, выполняющего операцию, должно быть право ручного зачисления в курсе Moodle. Сервисная учётная запись токена должна иметь возможность назначать роль учащегося. Если её идентификатор отличается от стандартного `5`, задайте `MOODLE_STUDENT_ROLE_ID` в `.env.local`. Курс без настроенных критериев завершения показывает прогресс по отслеживаемым активностям, если они есть.

Для панели прогресса в Docker закреплена совместимая пара Grafana 11.6.11 и Infinity 4.1.8. При обновлении версий проверьте загрузку плагина и запрос данных панели.

## Должности и подразделения

Администратор ведёт оба справочника в админ-панели. Чтобы назначить записи, откройте карточку пользователя в режиме редактирования. Поля необязательные. Чтобы удалить используемую запись справочника, сначала снимите назначение или выберите другую запись у связанных пользователей. При обновлении Docker существующая база дополняется автоматически.

## Пороги сложности

В `.env.local` можно задать `TASK_DIFFICULTY_MEDIUM_MIN` и `TASK_DIFFICULTY_MEDIUM_MAX` для средней сложности. Значения по умолчанию — 25 и 75. Границы средней категории включены. Значения ниже первой границы считаются лёгкими, выше второй — сложными. После изменения пересоздайте контейнер backend (`docker compose up -d backend`). Карточки и диаграмма получают пороги из API.

## Документация API

http://localhost:8000/docs доступна только администратору. В браузерном запросе входа используйте email и пароль администратора приложения. Swagger позволяет отдельно указать JWT через Authorize для вызова API. Токены действуют один час, содержат sub=email, user_id, role, exp. Изменение роли в БД учитывается сервером. После смены секретного ключа подписи нужно войти заново.

## Grafana

http://localhost:3000. Логин администратора Grafana — admin, пароль хранится в `.env.grafana.local`. Он отличается от пароля администратора приложения. Встроенные отчёты используют Viewer-доступ локального стенда. Публикация в интернет требует отдельной настройки TLS и единого доступа; текущие порты привязаны к loopback.

## Запуск без Docker

Требуется Python 3.10+ и Node для сборки frontend. Установите зависимости из requirements.txt, выполните `npm ci` и `npm run build` в frontend. Перед `python start.py` задайте в окружении SECRET_KEY и DB_PASSWORD из локальной конфигурации; не публикуйте их. `.env` содержит только несекретные defaults. PostgreSQL должен иметь pg_cron, совместимую схему и корректный пароль.

## Проверки

Штатные фикстуры pytests/conftest.py создают и удаляют таблицы. Полный набор запускайте только на отдельной тестовой базе DB_NAME_TEST. Производственную или пользовательскую базу для этих тестов не используйте. Локальные проверки исправлений выполняются изолированно с откатом транзакции и отключёнными почтой и внешними запросами.

Для прогона Locust задайте `LOCUST_USERS_JSON` как JSON-массив тестовых учётных записей. Каждая запись содержит `email`, `password` и необязательное логическое поле `can_manage` для сценариев менеджера или администратора.
